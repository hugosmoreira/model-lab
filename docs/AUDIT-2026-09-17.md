# Model Lab audit and continuation plan

Audited on 2026-09-17 (America/Los_Angeles), at commit
`ac8479891660ec9bdc89690c7283d82dafb0fcc6`. This describes the implementation
before the audit documentation changes. Findings below remain open.

## Assessment

The project is viable to continue. It already runs a complete local benchmark
workflow: provider adapters, generation, browser checks, optional judging,
persistence, live events, inspection and exports. The existing tests and
production build pass. A rewrite is not justified by this review.

It is not ready to promise secure execution of arbitrary generated code,
strict spending ceilings, or fully reproducible published comparisons.
Prioritize release hardening and evidence integrity before Leaderboard,
Judge Lab, more packs, or an installable binary.

The existing public plan is [ROADMAP.md](ROADMAP.md); architecture, security
policy, deployment and contributor documentation already exist. Source
comments refer to older numbered audit sections and implementation phases,
but there is no separate current, actionable implementation plan in the
tracked tree. The release sequence below supplies that missing ordering.

## Security review

A Standard Codex Security scan used an independent baseline, architecture
mapping and focused runner, API/store and frontend reviews. Findings were
reconciled against source by the parent reviewer. The canonical report is
attached to scan `81eef8dc-cbb4-44e7-aff3-1332eb9e2874`; security severities
below account for local deployment and prerequisites.

The scan reviewed 182 of 191 tracked files as implementation, documentation or
test evidence; eight PNG files were excluded and the lockfile was checked only
for relevant configuration. Workbench-measured usage across seven participating
threads was 24,043,748 total tokens: 23,927,970 input (22,862,720 cached) and
115,778 output. These are aggregate processing counts, not a dollar cost.

These are source-validated findings, not claims of a successful live attack.
Popup behavior, destructive memory exhaustion, real billing and browser local
network permission behavior were not exercised. S7 is independently supported
by the existing mock test's observed overspend.

Existing controls worth preserving: the iframe omits `allow-same-origin`;
React escapes model text; SQLite binds query parameters; Supabase credentials
stay server-side and the migration enables deny-by-default RLS; file routes
sanitize and contain paths; all three HTTP write routes enforce read-only
mode. Missing public authentication/rate limiting is explicitly documented,
so it was not reported as a newly discovered vulnerability.

The scan does not certify dependency CVEs, browser-engine vulnerabilities,
container contents, applied cloud policies or external proxy configuration.
Ignored secrets/private run data and Git history were excluded. Binary
screenshots and the dependency lockfile were not treated as audited application
implementation. A bounded tracked-source key-pattern search returned no matches;
that is not a historical or comprehensive secret scan.

## Benchmark correctness and reproducibility

These are release blockers even where they do not represent an unauthorized
security boundary.

1. **Artifact storage can overwrite another run's evidence.** Artifact and
   screenshot paths use four run-ID characters and 16 model-name characters.
   Distinct IDs can map to the same file; writes overwrite it, and exports copy
   the entire shared prefix directory. Use full identities or collision-resistant
   hashes, write once, and export only the run's recorded file references.
   Preserve compatibility with old bundles. Evidence:
   [store-fs.ts](../runners/build-arena/src/store-fs.ts#L36),
   [bundle.ts](../runners/build-arena/src/bundle.ts#L161).

2. **Concurrent pixel checks share mutable state.** One analyzer page stores
   `globalThis.__mlFrame`; loading and measuring a frame happen in separate
   awaited calls. Concurrent artifacts can overwrite the frame used for another
   artifact's measurements, including later minimap checks. Give each sample
   private analyzer state or serialize the complete measurement lifecycle.
   Also review shared browser shutdown when multiple runs overlap. Evidence:
   [browser-checks.ts](../runners/build-arena/src/checks/browser-checks.ts#L253),
   [analyzeFrame](../runners/build-arena/src/checks/browser-checks.ts#L719),
   [parallel runner](../runners/build-arena/src/run.ts#L1027).

3. **Missing data silently becomes demo evidence.** Unknown IDs, unavailable
   stores and failed run lookups return the fixture view. The smoke check
   reproduced successful result/share pages for a nonexistent run.
   Return an explicit 404 or storage error; reserve fixtures for an explicit
   demo route. Evidence:
   [loaders.ts](../apps/web/lib/server/loaders.ts#L366).

4. **Bundles cannot fully reconstruct the advertised configuration.** The
   fingerprint hashes the full RunnerConfig, but the exporter omits its full
   configuration, raw directory and native objective task definitions; it
   hardcodes `scorers: ["browser"]` and `kind: "build-arena"`.
   Both run creation paths set `gitCommit: null`. Export a versioned replay
   contract with actual mode/scorers, settings, endpoints, tasks, evidence and
   revision; verify a round trip reproduces the fingerprint without secrets.
   Evidence: [bundle.ts](../runners/build-arena/src/bundle.ts#L63),
   [run.ts](../runners/build-arena/src/run.ts#L337),
   [run-service.ts](../apps/web/lib/server/run-service.ts#L475).

5. **Blind voting reveals identities before the vote.** Visible history
   renders both short names for unfinished pairs. Keep unfinished pair labels
   neutral throughout the page, and make final-vote writes atomic to prevent
   concurrent overwrites. Evidence:
   [HeadToHeadClient.tsx](../apps/web/components/compare/HeadToHeadClient.tsx#L112),
   [HistoryPanel.tsx](../apps/web/components/compare/HistoryPanel.tsx#L43),
   [vote route](../apps/web/app/api/runs/[runId]/votes/route.ts#L75).

6. **Score-source labeling is still inconsistent.** One human rating changes
   Results chart labels to human scoring while unrated endpoints retain browser
   scores. Unscored scatter points are plotted at zero. CSV, alt text and social
   drafts use a generic visual label even when the card uses another source.
   Select scores per source, preserve missing values, and carry source plus
   sample count through every export. Evidence:
   [Results](../apps/web/app/runs/[runId]/results/page.tsx#L285),
   [loaders](../apps/web/lib/server/loaders.ts#L416),
   [export-data.ts](../apps/web/lib/share/export-data.ts#L13).

7. **Human annotation validity differs across stores.** SQL-backed inserts can
   accept nonexistent run/sample references; loaders average these annotations.
   Validate run, endpoint and sample membership consistently across all backends,
   preserving append-only corrections. Extend the conformance suite with
   invalid-reference and concurrent-final-vote cases.

## Open-source professionalism

The repository already has an MIT license, contribution guide, code of conduct,
private vulnerability-reporting link, issue/PR templates, citation metadata,
CI, Dependabot and a public roadmap. The release work is primarily about
matching behavior to those promises.

- **Make demo content explicit everywhere.** Mission Control remains mostly
  fixtures and run listings always merge fixture history. The top bar decides
  demo/live from the store backend, not key presence. Adding a key does not
  replace all illustrative statistics as the current docs suggest. Use a
  consistent demo/data-source policy and honest empty states.
- **Remove misleading controls.** The search button advertises a shortcut but
  has no handler. Several settings remain fixture displays. Disable or label
  unfinished interactions consistently; the existing Leaderboard/Judge Lab
  `soon` labels are a useful precedent.
- **Correct persistence documentation.** The Supabase guide tells users to create
  a bucket for artifacts, but no bucket upload/download consumer exists.
  Metadata can be remote while screenshots, raw output and bundles remain local.
  `MODEL_LAB_DATA_DIR` does not move the default SQLite database.
- **Align startup and network promises.** The CLI reads root dotenv only, unlike
  the web's app-local overrides. Ollama-only auto mode is mocked unless explicitly
  forced real. Health probes still contact providers in forced mock mode.
  Document these distinctions or unify the implementation.
- **Keep published evidence traceable.** The committed example predates the
  current scoring taxonomy; retain it unchanged and label that difference.
  Publish an n=3 comparison only after storage, concurrency, source labels and
  replay integrity are fixed.
- **Verify release operations separately.** Repository code cannot prove GitHub
  private reporting/discussions are enabled, branch protection is configured,
  image publishing is clean, or the configured contact channels accept private
  reports. The Code of Conduct suggests GitHub direct messages; supply a verified
  usable private reporting channel. Do not invent contact details.
- **Strengthen the release gate.** Add focused security and integration tests for
  the concrete issues above; browser interaction/accessibility and a clean
  checkout/container verification remain separate follow-up work. Pinning CI
  actions to immutable revisions and explicit minimal token permissions are
  sensible maintenance hardening, not proof of an exploitable workflow.

## Ordered continuation

| Stage | Deliverable | Acceptance evidence |
| --- | --- | --- |
| 1. Execution and request safety | Trusted preview policy, context-wide network restrictions, shared mutation-origin guard, recursive secret exclusions, bounded diagnostics/streams | Adversarial regression fixtures make no external requests; cross-origin writes cause no effects; sentinel credentials stay out of images; streams/logs terminate at defined bounds |
| 2. Spending and evidence integrity | Pre-call budget reservations, full-identity immutable storage, private analyzer state, atomic vote/annotation validation | First/final/concurrent/retry budgets pass; colliding legacy prefixes cannot overwrite new evidence; concurrent distinct frames remain independent; invalid references rejected |
| 3. Honest product and replay | Explicit missing/demo states, blind labels, per-source charts/exports, complete versioned bundles and accurate docs | Unknown run returns 404; partial human ratings do not relabel browser values; missing remains missing; exported configuration reproduces its fingerprint |
| 4. Public release candidate | Fresh install/container checks, browser/accessibility pass, validated reporting channels, n=3 evidence | Clean CI plus release checklist; only mock integration checks in CI; real benchmark costs chosen deliberately |
| 5. Existing feature roadmap | More packs, Judge Lab, comparable-run Leaderboard, eval adapters, installable CLI | Build on the corrected contracts; retain n, source and uncertainty labels |

Start Stage 1 with the shared HTTP mutation guard and recursive Docker secret
exclusions, alongside artifact-policy regression fixtures. Those changes are
small enough to review independently. Complete the isolated-browser work before
claiming hostile artifact execution is network-free.

This audit updates documentation and the continuation order. It does not claim
that the listed implementation defects have been repaired.
